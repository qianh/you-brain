# you-brain 部署与运行

> 版本：v1.0 ｜ 日期：2026-10-27
> 配套：[README](../README.md) ｜ [技术方案](./技术方案.md) ｜ [产品说明](./产品说明.md)

本文覆盖三种跑法：源码开发、桌面端安装包、纯服务器部署。服务器部分是重点——无界面机器上有几处与桌面端不同的地方（登录、密钥、开机自启），单独说明。

---

## 1. 三种形态怎么选

| 形态 | 适用场景 | 采集本机会话 | 界面 | 常驻方式 |
|---|---|---|---|---|
| **源码运行** | 开发、调试、临时试用 | 是 | 浏览器打开本地端口 | 手动 `you-brain daemon` |
| **桌面端** | 日常使用的电脑 | 是 | 菜单栏 + 完整窗口 | Tauri 外壳 + 开机自启 |
| **服务器端** | 7×24 在线，通常担任主设备 | **否** | 远程通过 SSH 隧道看 | systemd 用户单元 |

三者跑的是**同一个核心程序**（`packages/core` + `packages/cli`），只是启动参数和角色配置不同。服务器端不是另一个项目，是同一个二进制的另一种角色。

同一个 Google 账号下的所有设备组成一个整体：会话原文各设备自管，话题册与数字分身全量同步。任何时刻只需一台设备在线。

---

## 2. 前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | macOS（arm64 / x64）或 Linux（x86_64 / aarch64） |
| Google 账号 | 用于存放数据；Drive 空间按会话原文实际占用计 |
| 模型后端 | 一个 API Key（DeepSeek / GLM / Qwen / Kimi / OpenAI / Claude / 自建 OpenAI 兼容端点 / Ollama），或本机已登录的 AI CLI（`grok` / `claude` / `codex` / `gemini` / `opencode`） |
| OAuth 凭据 | 自己的 Google Cloud 项目，见第 3 节 |
| 源码运行时 | Bun ≥ 1.2.19 |

服务器额外要求：`systemd`（用于开机自启）、能访问 `accounts.google.com` 与 `www.googleapis.com`。

---

## 3. 准备 OAuth 凭据（所有人）

you-brain 默认走**每个人自己的 Google Cloud 项目**，不依赖构建时内置的凭据，也不受「测试用户最多 100 人」的限制。

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，新建一个项目
2. 「API 和服务 → 库」里启用 **Google Drive API**
3. 「API 和服务 → OAuth 同意屏幕」：
   - User type 选 **Internal**（有 Google Workspace 且同域名），或选 External
   - 选 External 时，把应用**发布到 Production**（Publishing status）
4. 「凭据 → 创建凭据 → OAuth 客户端 ID」：
   - 应用类型选 **桌面应用**
   - 记下 Client ID（形如 `1234567890-xxxx.apps.googleusercontent.com`）和 Client Secret

> **关于 Testing 状态**：如果应用停留在 Testing，Google 只给 7 天有效的 refresh token，之后必须重新登录。选 Internal 或发布到 Production 就不会过期。这是 Google 的策略，不是 you-brain 的限制。

权限范围是完整的 Drive 权限（`https://www.googleapis.com/auth/drive`），用于读取插件、外部 bot 以及用户自己放进 Drive 的文件。

## 4. 源码运行（开发用）

```bash
bun install
bun run typecheck
bun test

# 交互式配置
bun packages/cli/src/index.ts setup

# 前台运行
bun packages/cli/src/index.ts daemon
```

`setup` 可重复执行，会跳过已完成的步骤，中途退出后重新跑会接着上次的进度。

常见参数：

```bash
bun packages/cli/src/index.ts setup --yes                 # 非交互，接受默认值
bun packages/cli/src/index.ts setup --oauth custom \
  --client-id xxx.apps.googleusercontent.com --client-secret <secret>
bun packages/cli/src/index.ts setup --provider deepseek --model deepseek-chat --api-key sk-xxx
bun packages/cli/src/index.ts setup --no-integrations     # 不写任何 AI 客户端配置
```

## 5. 桌面端

### 5.1 打包

```bash
bun run build:daemon                              # 编译 Web 界面 + daemon + vendor + sidecar
bun run --cwd apps/desktop bundle --bundles app   # macOS：只产出 .app
bun run --cwd apps/desktop bundle                 # macOS：产出 .app 与 DMG，发布时用
```

`build:daemon` 默认走 npmmirror，不用再手动设置镜像变量；已设置的 `BUN_CONFIG_REGISTRY`、`npm_config_registry` 优先。依赖没变时直接复用 `dist/.build-cache/`，不联网；设置 `YOU_BRAIN_NO_BUILD_CACHE=1` 可强制重装。实测数据和排查方法见仓库根目录的 `CLAUDE.md`。

Linux 用 `apps/desktop/scripts/bundle-linux.sh`（只能在 Linux 上跑，产出 deb 与 AppImage），或手动触发 `.github/workflows/desktop-linux.yml`。

产物落在 `dist/app.noindex/`。

### 5.2 开发时把新构建装进现有 .app

```bash
bun run install:app                 # 默认装到 /Applications/U-Brain.app
bun run install:app /path/to/U-Brain.app
```

脚本不重建桌面外壳，改过 `apps/desktop` 要走 5.1 的完整打包。它会先停掉正在运行的副本，整体替换 `Resources/{web,vendor,dsh}` 与可执行文件，然后重新 ad-hoc 签名。**签名变化会让 macOS 拒绝之前的钥匙串条目**，装完之后需要重新登录一次 Google。

### 5.3 运行

装好后从「应用程序」启动即可。菜单栏常驻，不占 Dock；点击图标打开面板，面板里可以跳到完整窗口。

桌面端由 Tauri autostart 插件在登录时拉起外壳，外壳再拉起 daemon。不需要手动装服务。

## 6. 纯服务器部署

服务器端没有图形界面，也不采集本机会话（本机没有 CLI 会话可采），职责是：提炼网页会话、每日全局沉淀、协议同步，以及对外提供 Web UI 和 MCP。

### 6.1 获取安装包

服务器包是 tar.gz，包含编译好的二进制、Web 界面和原生依赖（`onnxruntime-node`、`sharp`、嵌入模型）。

**只能在 Linux 上构建**：`bun build --compile` 不支持交叉编译，vendor 里的原生二进制也是本机的。

```bash
# 方式一：CI（推荐）
# 在 GitHub Actions 手动触发 server-linux.yml，下载 artifact

# 方式二：在 Linux 机器上自行构建
bun install
bun run --cwd apps/web build
bun run build:server               # 产出 dist/server/you-brain-<version>-<triple>.tar.gz
```

CI 构建要装 Node 24（DSH 运行时要求 Node ≥ 24.9），`server-linux.yml` 已带 `setup-node`。2026-11-21 手动触发，x86_64 与 aarch64 两个包都出成功了。偶发的 `onnxruntime-node` postinstall 下载超时是 runner 网络问题，直接重跑即可。

CI 出的包**不含内置的官方 OAuth 凭据**（仓库没有配对应 Secret），服务器上要按 6.3 自带凭据。

**方式三：在 VPS 上直接拉源码构建（推荐给海外 VPS）**

仓库公开，VPS 直连 GitHub 很快；从本机用 `scp` 往海外 VPS 传 78MB 的包实测会在中途卡死。构建约几分钟，4 核 / 4GB 内存足够。

```bash
# 前置：git、unzip、xz-utils（Ubuntu：apt install -y unzip xz-utils）
curl -fsSL https://bun.sh/install | bash
# Node 24 只用来打包 DSH，装在家目录即可，不动系统自带的 Node
V=$(curl -fsSL https://nodejs.org/dist/index.json | grep -o '"v24\.[0-9.]*"' | head -1 | tr -d '"')
mkdir -p ~/.local/node24
curl -fsSL https://nodejs.org/dist/$V/node-$V-linux-x64.tar.xz | tar -xJ -C ~/.local/node24 --strip-components=1
export PATH=$HOME/.bun/bin:$HOME/.local/node24/bin:$PATH

git clone --depth 1 https://github.com/qianh/you-brain.git ~/you-brain
cd ~/you-brain && bun install
bun run --cwd apps/web build
bun run build:server               # 产出 dist/server/you-brain-<version>-<triple>.tar.gz
```

升级时 `git pull --ff-only` 后重跑后三行，再执行包内 `install.sh` 并重启服务。

包内结构：

```
you-brain-<version>-<triple>/
  bin/you-brain                    # 编译后的单一可执行文件
  lib/you-brain/web/               # Web 界面静态产物
  lib/you-brain/vendor/node_modules/  # sharp、onnxruntime、嵌入模型运行时
  install.sh
```

桌面包改名 U-Brain 后，Linux 桌面包的资源目录是 `lib/U-Brain`；服务器包保留 `lib/you-brain`，升级时目录不变。程序两个目录都认，会自己找到界面和原生依赖，不需要额外配置环境变量。

### 6.2 安装

```bash
tar -xzf you-brain-0.1.0-x86_64-unknown-linux-gnu.tar.gz
cd you-brain-0.1.0-x86_64-unknown-linux-gnu
./install.sh
```

默认装到 `~/.local/bin/you-brain` 和 `~/.local/lib/you-brain/`。自定义前缀：

```bash
PREFIX=/opt/you-brain ./install.sh
```

脚本会**整体替换** `lib/you-brain`（不是覆盖复制），避免旧版本残留的 `web/`、`vendor/` 导致界面或原生模块错乱。

### 6.3 首次设置（无界面登录）

```bash
you-brain setup --server --skip-brainhub --oauth custom \
  --client-id xxx.apps.googleusercontent.com --client-secret <secret>
```

`--server` 会：

- 把角色写成 `role = "server"`（`config.toml`）
- 关闭全部采集来源（服务器上没有 CLI 会话）
- 跳过 AI 客户端接入与首次回填
- 登录走**无界面模式**：固定回调端口 53682，不尝试拉起浏览器

`--skip-brainhub` 在非交互终端里建议加上，否则会询问是否接管 BrainHub 然后退出。

登录时终端会打印：

```
这台机器没有浏览器。先在你自己的电脑上执行：
  ssh -N -L 53682:127.0.0.1:53682 user@your-server
保持这个终端窗口开着，然后在浏览器里打开下面的链接：
https://accounts.google.com/o/oauth2/v2/auth?...
```

在**自己电脑**上执行那条 `ssh` 命令，然后用浏览器打开链接完成授权。授权完成后服务器上的命令会自动继续。链接有效期 10 分钟。

> 也可以先跑 `you-brain setup --server --yes` 把服务装起来（不登录），之后再在 Web 界面「设置 → 账户与 Drive」里登录并填凭据。

**`setup --yes` 只写凭据，不发起登录。** 带 `--oauth custom --client-id … --client-secret …` 跑完后：

1. **重启服务**：运行中的 daemon 不会重新读凭据，仍会报「此版本未内置官方 OAuth 凭据」。
2. 在服务器本机调 `POST /api/actions/google-login`（Bearer token 在 `<数据目录>/daemon.json`），它会阻塞到授权完成；授权链接从 `GET /api/status` 的 `login.authorizationUrl` 取。
3. 在自己电脑上开隧道 `ssh -N -L 53682:127.0.0.1:53682 <用户>@<服务器>`，再在浏览器打开授权链接。授权成功后接口返回「已使用 xxx 登录」，隧道可以关掉。

**没有自己的 OAuth 项目时**：桌面端构建用的官方凭据在构建机的 `~/.config/you-brain/release.env`，可以用 `--oauth custom` 填给服务器。注意官方凭据目前是 Testing 状态，refresh token 7 天过期，要每周重新登录一次；长期运行的主设备应换成自己项目的凭据（第 3 节）。

**登录后以 Drive 为准**：登录并首次同步后，`roles.json` 会被 Drive 上的内容覆盖。登录前在服务器上设的主设备不会保留，**要在登录、同步完成之后再设主设备**（6.5）。

### 6.4 常驻

```bash
you-brain service install          # 生成并启用 systemd 用户单元
sudo loginctl enable-linger $USER  # 无人登录时也能开机自启
you-brain service status           # 查看状态、pid、日志位置
```

单元文件：`~/.config/systemd/user/you-brain.service`，内容由 `you-brain service install --print` 可以预览。

如果没有 `loginctl enable-linger`，服务只会在该用户登录后启动——服务器重启后可能一直不跑。这一步需要 root。

**运行身份**：普通用户和 root 都可以。

- **root**：`loginctl enable-linger root`，`systemctl --user` 要带 `XDG_RUNTIME_DIR=/run/user/0`。root 下不受 Ubuntu 24.04 对非特权用户命名空间的限制（见 6.8 的 `bwrap`），已有的 grok 登录也能直接用。
- **普通用户**：`systemctl --user` 要带 `XDG_RUNTIME_DIR=/run/user/<uid>`，并设置 `DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/<uid>/bus`；从 root 切换时用 `runuser -u <用户> -- env … bash -c '…'`，不要用 `pkill -f` 匹配命令行里带自己名字的进程，会把自己的 shell 杀掉。
- **单元文件里的 PATH 是安装时的环境**：`service install` 会把当时的 `PATH` 写进单元。要让 daemon 找得到 `grok` 等命令，先 `export PATH=$HOME/.local/bin:$PATH` 再安装。

**`WorkingDirectory` 带引号的旧 bug**：早于提交 `684516a` 的版本会生成 `WorkingDirectory="/home/<用户>"`，systemd 报 `path is not absolute`，单元起不来。升级即可；旧包可手动去掉引号后 `systemctl --user daemon-reload`。

**搬数据目录（换运行用户）**：把 `<数据目录>` 整个复制过去（排除 `daemon.json`、`daemon.lock`、`llm-cli`），设备 id 不变，Drive 里不会多出一台设备。**但 `secrets.json` 里的 key 带有配置文件路径的哈希**（`config-<sha256(config.toml 绝对路径)前 32 位>` 与 `oauth-client-secret:<同一哈希>`），路径一变就读不到，表现为 Drive 「不可达」、状态里 `AUTH_REQUIRED`。要把这两个 key 的哈希部分改成新路径对应的值（只改 key 名，不动值）后重启。

其他管理命令：

```bash
you-brain service install --no-start   # 只写单元，不立即启动
you-brain service uninstall            # 停止并删除单元
you-brain uninstall                    # 停止服务 + 撤销 AI 客户端接入 + 可选删除数据
```

### 6.5 设为主设备

每日全局沉淀由主设备负责：

```bash
you-brain devices                     # 列出所有设备，找到这台机器的 id
you-brain devices --set-main <id>
you-brain devices --set-web-processor <id>   # 可选，默认跟随主设备
```

服务器作为主设备的典型配置是：`capabilities` 为 `["refine", "consolidate"]`（不含 `capture`），设备页会显示为「服务器」。

**网页会话处理设备默认跟随主设备**（`webProcessor ?? mainDevice`），所以服务器成为主设备后，设备页上它会同时带「网页会话」标签：浏览器插件抓到 Drive `inbox/web-*` 的网页版 AI 会话都由它提炼（60 秒检查一次，文件空闲 5 分钟后处理，每次最多 3 条），用的是**服务器自己的模型**。各台电脑采集的 CLI 会话仍由各自设备提炼，不受影响。

切换主设备前先确认服务器已配好模型（6.8），否则每日沉淀会因 `NO_LLM` 被跳过。

### 6.6 远程访问 Web 界面

daemon 只监听 `127.0.0.1`，不对外暴露。端口是随机的，以 `status` 输出为准：

```bash
you-brain status
# ...
# Web 界面：http://127.0.0.1:52490
#   远程查看：ssh -N -L 52490:127.0.0.1:52490 <用户>@<这台机器>
```

在自己电脑上执行那条隧道命令，然后浏览器打开 `http://127.0.0.1:52490`。也可以用 Tailscale 之类的组网工具直接访问回环地址。

**不要**改成监听 `0.0.0.0`：API 只有一个静态 bearer token，暴露到公网等于把全部会话原文和数字分身公开。

### 6.7 服务器上的密钥存放

Linux 桌面端用 `secret-tool`（Secret Service）存密钥，无界面的服务器通常没有这个服务。服务器角色会自动改用**文件后端**：

```
<dataDir>/secrets.json      权限 0600
```

可以用环境变量覆盖：

| 变量 | 作用 |
|---|---|
| `YOU_BRAIN_SECRET_BACKEND=file` | 强制用文件后端 |
| `YOU_BRAIN_SECRET_BACKEND=keychain` | 强制用系统钥匙串 |
| `YOU_BRAIN_SECRETS_FILE=/run/secrets/you-brain.json` | 指定密钥文件路径 |

文件里存的是 refresh token、OAuth client secret 和模型 API Key，格式是 `{"<service>\0<account>": "<value>"}`。备份和迁移时注意这个文件等价于账号凭据。

### 6.8 模型：各设备自己维护

`llm`（会话提炼、网页会话处理）和 `consolidateLlm`（每日沉淀）**只存本机，不随 Drive 同步**（提交 `171cad5`）：

- 拉取 Drive 的 `shared.json` 时忽略其中的模型字段，始终保留本机的。
- 本机改模型时，推到 Drive 的补丁不带这两项，不会影响其他设备（含尚未升级的旧版本）。
- 新设备不再继承别的设备的模型，要自己配。
- 桌面端常用的 `magpie` 是本机网关（`127.0.0.1:3425`），**Linux 没有 Magpie**，服务器上不能选它；也不要期望 Magpie 里选的思考强度出现在服务器上。

**用本机订阅的 grok CLI，并指定 Extra High**

grok-cli 的调用默认 `--effort low`（grok 的全局默认可能是 xhigh，会慢约 3 倍）。在模型名后加后缀指定强度，`-m` 不带后缀，`--effort` 取后缀：

| 模型名 | 实际参数 |
|---|---|
| `grok-4.7-build-fast` | `-m grok-4.7-build-fast --effort low` |
| `grok-4.7-build-fast:xhigh` | `-m grok-4.7-build-fast --effort xhigh`（界面上的 4.7 Fast Extra High） |

后缀可选 `low` / `medium` / `high` / `xhigh`。xhigh 比 low 慢，CLI 默认超时 300 秒，沉淀或提炼超时再调大。

**在服务器上准备 grok**

1. 安装 grok CLI，放在运行 daemon 的用户的 `PATH` 里（如 `~/.local/bin/grok`）。
2. 无界面登录用设备码，不需要隧道：`grok login --device-auth`。它打印 `https://accounts.x.ai/oauth2/device?user_code=…`，在自己电脑的浏览器里打开并确认。登录凭据存在 `~/.grok/auth.json`，**每个用户各登各的**，不要把别的用户的 `auth.json` 复制过来（令牌被两处使用可能互相失效）。
3. 复制二进制给另一个用户时，用 `install -D` 会把中间目录建成 root 属主，之后 `grok login` 报 `Failed to save credentials: Permission denied`，要 `chown -R <用户> ~/.grok ~/.local`。
4. 装 `bubblewrap`：`apt install -y bubblewrap`。you-brain 调 grok 时带 `--sandbox read-only`，Linux 上没有 `bwrap` 会报 `this sandbox could not enforce its deny list`。
5. **Ubuntu 24.04 上非 root 用户的 `bwrap` 仍会失败**：`bwrap: setting up uid map: Permission denied`，这是 AppArmor 对非特权用户命名空间的限制。用 root 运行 daemon 不受影响（实测 `bwrap`、grok 沙箱、xhigh 都正常）；普通用户要给 `/usr/bin/bwrap` 放行用户命名空间，本次部署没有采用，未验证。

**设置并验证**

在服务器本机通过 daemon 接口设置，改完立即生效（也可以在 Web 界面「设置」里改）：

```bash
# PORT 与 TOKEN 取自 <数据目录>/daemon.json
curl -s -X PUT -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
  http://127.0.0.1:$PORT/api/config \
  -d '{"llm":{"provider":"grok-cli","model":"grok-4.7-build-fast:xhigh","baseUrl":""},
       "consolidateLlm":{"enabled":false,"provider":"grok-cli","model":"grok-4.7-build-fast:xhigh","baseUrl":""}}'

# 实测连通（body 三个字段都必填）
curl -s -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \

### 6.9 跨设备派活与自有 VPS 中转

多台设备共用一个 Telegram Bot、并让一台设备把任务派到另一台设备的 T3，需要一个中转。中转跑在你自己的 VPS 上（Bun + systemd + Caddy，只监听 `127.0.0.1`），部署和切换步骤见 [`services/telegram-relay/README.md`](../services/telegram-relay/README.md)，决策见 [ADR-0007](./adr/0007-中转迁自有VPS并承载设备间派活.md)，协议见 [跨设备派活-协议](./跨设备派活-协议.md)。

要点：

- 这不改变 §6.6 的红线：daemon 仍只监听 `127.0.0.1`，设备只主动连出一条 WebSocket 到中转。
- 中转的 `/admin/*` 只给 VPS 本机用，Caddy 对外必须 404；邀请码和吊销用 `bun src/admin.ts invite|revoke <设备ID>|devices`（读取 `RELAY_KEY`，不要写进命令行参数）。
- 设备入网：在 VPS 上生成邀请码，在新设备的「设置 → 集成 → Telegram」里填中转地址和邀请码；邀请码 10 分钟有效、只能用一次。入网后设备使用专属令牌（存钥匙串），旧共享密钥只在过渡期保留。
- 目标设备默认**不接受**派活。要接收，在该设备的「设置 → 集成 → 跨设备派活」里开启、勾选允许的发起设备和项目，并确认权限上限（默认 `auto`，`full-access` 需要手动开）。
- 全部设备入网后，把 `/etc/u-brain-relay.env` 里的 `RELAY_ACCEPT_LEGACY_KEY` 设为 `false` 并重启中转。
- 在 VPS 的 T3 里跑主控 Agent 时，确认 `you-brain mcp` 已写入该 Agent CLI 的配置，并在一个 T3 会话里能看到 `list_devices` 等四个工具。

| `YOU_BRAIN_WEB_DIR` | Web 界面目录 |
| `YOU_BRAIN_MODEL_CACHE` | 嵌入模型缓存目录 |

### 7.2 数据目录内容

```
config.toml          设备身份、角色、OAuth 模式、账号（0600）
shared.json          采集规则、模型 Provider、话题册参数、提醒设置
roles.json           主设备 / 网页会话处理设备 / 时区

本地 SQLite 是 Drive 数据的**派生副本**，删掉可以从 Drive 重建；`secrets.json` 和 `config.toml` 则不可重建。

### 7.3 备份

需要备份的只有：

- `config.toml`（设备身份，`deviceId` 一旦写入不可更改）
- `secrets.json`（服务器角色的授权）

其余都在 Drive 上或可重建。

## 8. 运行机制

### 8.1 进程模型

```
you-brain daemon      常驻核心服务：采集、上传、提炼、同步、调度、本地 HTTP API
you-brain mcp         MCP stdio 服务，由 AI 客户端拉起，只读本地库
you-brain <command>   CLI，通过本地 HTTP API 与 daemon 通信
Tauri 外壳            仅桌面端：菜单栏 + WebView，启动时确保 daemon 在运行
```

同一台设备只允许一个 daemon，通过锁文件保证。

### 8.2 主要周期

| 周期 | 间隔 |
|---|---|
| 主循环 tick | 1 秒 |
| 事件 flush | 30 秒 |
| 心跳（写入设备表） | 5 分钟 |
| Drive 拉取 | 60 秒（有界面订阅时 5 秒） |
| 全量扫描兜底 | 10 分钟 |
| 提醒生成 | 10 分钟 |
| 沉淀检查 | 10 分钟 |
| 搜索索引更新 | 60 秒 |
| 网页会话检查 | 60 秒 |
| 数字分身刷新 | 24 小时 |

采集以文件监听为主（250 毫秒防抖），全量扫描只是兜底。

### 8.3 会话提炼触发

- **本地 CLI 会话**：会话空闲 5 分钟后，由产生它的设备先上传再提炼
- **网页会话**：处理设备通过 Drive 变更游标发现，文件空闲 5 分钟后提炼

会话继续增长时只把「上次提炼结果 + 新增消息」交给模型，不重复处理全文。

## 10. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `you-brain status` 显示 daemon 未运行 | 服务没装或已退出 | `you-brain service status`；服务器上确认执行过 `loginctl enable-linger` |
| 登录打印「本地授权端口 53682 被占用」 | 上一次登录没结束，或别的进程占了端口 | 关掉占用进程后重试；`lsof -i:53682` 查看 |
| 授权链接打开后一直等到超时 | SSH 隧道没开或已断开 | 保持隧道窗口开着，重新点登录 |
| 每 7 天要求重新登录 | OAuth 应用停在 Testing | 把应用发布到 Production，或 User type 改为 Internal |
| `Secret Service is unavailable` | 桌面 Linux 没有 gnome-keyring / kwallet | 启动钥匙串服务，或设 `YOU_BRAIN_SECRET_BACKEND=file` |
| 服务器上 `setup` 报「不是交互终端」 | 缺少 `--yes` 或 `--skip-brainhub` | 补上对应参数 |
| 界面显示「没有找到 Web 界面」 | `web/` 目录缺失 | 重新运行 `install.sh`；或设 `YOU_BRAIN_WEB_DIR` |
| 采集为空 | 服务器角色不采集本机会话 | 正常行为；桌面端才会采集 |
| `native-check` 失败 | vendor 里的原生模块与平台不匹配 | 重新在目标平台构建 |
| systemd 报 `WorkingDirectory= path is not absolute` | 旧版本生成的单元里路径带了引号 | 升级到 `684516a` 之后，或手动去掉引号并 `daemon-reload`（6.4） |
| 状态里 `AUTH_REQUIRED`，Drive 不可达，但 `secrets.json` 里有密钥 | 搬过数据目录，密钥 key 里的路径哈希对不上 | 重命名两个 key 的哈希后重启（6.4） |
| `setup` 写了凭据，登录仍提示「未内置官方 OAuth 凭据」 | daemon 没重启，没读到新凭据 | 重启服务，再走 6.3 的登录流程 |
| 登录前设的主设备，登录后又变回别的设备 | 首次同步后 `roles.json` 以 Drive 为准 | 登录、同步完成后再设主设备 |
| `llm-test` 报 `this sandbox could not enforce its deny list`、`bwrap exec failed` | 没装 `bubblewrap` | `apt install -y bubblewrap`（6.8） |
| `bwrap: setting up uid map: Permission denied` | Ubuntu 24.04 限制非特权用户命名空间 | 用 root 运行，或给 `bwrap` 放行（6.8） |
| `grok login` 报 `Failed to save credentials: Permission denied` | `~/.grok` 属主是 root | `chown -R <用户> ~/.grok ~/.local` |
| `Not signed in` | 该用户没登录 grok | `grok login --device-auth`（6.8） |
| 沉淀因 `NO_LLM` 被跳过，或模型是 `magpie` | 服务器上没有本机模型，或沿用了旧的同步值 | 按 6.8 设置本机模型，并关掉或改掉 `consolidateLlm` |

日志：

```bash
# 服务器（systemd 用户单元）
journalctl --user -u you-brain -f

# macOS 或前台运行
tail -f <数据目录>/logs/daemon.log
```

## 排查 daemon 内存

安装版的 daemon 把 stderr 丢掉了，要看内存只能打开追踪开关：

```bash
launchctl setenv YOU_BRAIN_MEMORY_TRACE 1
osascript -e 'quit app "U-Brain"'
pkill -TERM -f '/Applications/U-Brain.app/Contents/MacOS/you-brain daemon'   # 只退桌面外壳时 daemon 会留下，不会带上新环境
open -a /Applications/U-Brain.app
```

`<数据目录>/memory-trace.jsonl` 每 30 秒记一行进程 RSS、JS 堆和最多的对象类型；每个后台阶段（scan、pull、flush、searchSync、refineBackfill、notion……）结束时另记耗时、RSS 变化和新增对象数。追踪会遍历堆，有开销，用完按同样步骤 `launchctl unsetenv YOU_BRAIN_MEMORY_TRACE` 后重启并删掉该文件。

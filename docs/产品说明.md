# you-brain 产品说明

> 版本：v1.1 ｜ 日期：2026-10-26 ｜ 状态：P0、P1 与 Webhook 已实现，已在真实 Drive 与真实模型上跑通主要链路；完整验收未走完，见[进度.md](./进度.md)
> 配套文档：[技术方案.md](./技术方案.md) ｜ [进度.md](./进度.md)

## 1. 一句话定义

**你在任何设备上、和任何 AI 聊过的内容，都会被自动收集到你自己的 Google Drive；白天实时提炼成"今日话题"，每天沉淀进数字分身和话题册；换一台设备马上能接上，没跟进的话题会被提醒。**

you-brain 是一个开源的个人 AI 记忆中枢，是 BrainHub MCP 的重写和升级版。

## 2. 要解决的问题

| 痛点 | you-brain 的回答 |
|---|---|
| 在 Claude Code、Codex、Grok、Cursor、网页 AI 之间来回切换，上下文散落各处 | 所有来源的会话自动汇总到一处 |
| 换一台电脑，不知道今天在别的设备上聊了什么 | 每台设备都有完整的提炼数据，打开就能看到今日话题 |
| 聊过的事情没有下文，慢慢就忘了 | 话题册记录每个话题的结论和待办，停滞了会主动提醒 |
| 每个 AI 都不认识我，要反复交代偏好 | 数字分身自动接入各 AI CLI，按需提供完整画像 |
| 用户不想当人肉搬运工 | 采集、上传、提炼、同步、提醒全部自动 |

## 3. 设计原则

1. **数据归用户所有**：原文和提炼结果都存放在用户自己的 Google Drive，不经过任何维护者的服务器。
2. **国产模型一等公民**：DeepSeek / GLM / Qwen / Kimi 与 GPT / Claude 同等对待，模型后端可插拔。
3. **本地优先**：每台设备保存完整的提炼数据，断网也能看话题和概要。
4. **不依赖某台机器一直在线**：同步走 Drive，任何设备都可以随时加入或离开。
5. **用户只表达意图**：配置一次，长期免维护；有异常自动标出来。
6. **数据一视同仁**：所有会话走同一条管线，不分级。
7. **对第三方工具的改动须征得同意并且可以撤销**：写入 AI 工具配置之前必须先询问，只改自己的托管段落，卸载时全部还原。
8. **开放协议**：Drive 上的数据格式是公开的、带版本号的协议，外部 bot 和其他项目可以按协议读写。

## 4. 核心概念

| 概念 | 含义 |
|---|---|
| **会话原文** | 一次 AI 对话的完整内容（只保留可见文本和图片，已脱敏）。一个会话对应 Drive 上的一个文件，内容持续原地更新，链接永远不变 |
| **会话提炼** | 对单个会话的提炼结果：标题、概要、所属话题、结论、待办。会话空闲后自动生成，会话继续增长时增量更新 |
| **今日视图** | 当天所有设备、所有来源的会话及其提炼结果 |
| **话题** | 跨会话、跨天聚合的一件事，比如"you-brain 设计"。包括状态、概要、结论、待办和所有相关会话的链接 |
| **话题册** | 所有话题的集合，分为**活跃区**（默认 10 个）和**历史区** |
| **数字分身** | 关于用户的长期画像，由一组文件组成：全量版、精简版、编码版 |
| **设备** | 安装了 you-brain 的一台电脑或服务器。同一个 Google 账号下的所有设备组成一个整体 |
| **主设备** | 负责每日全局沉淀的那台设备，由用户指定 |
| **网页会话处理设备** | 负责提炼浏览器插件上报的网页会话的那台设备，默认就是主设备 |
| **虚拟设备** | 按协议接入的外部 bot（如 Muse、Grok Bot），可以代替主设备完成全局沉淀 |

## 5. 产品形态

### 5.1 组成

| 组件 | 说明 |
|---|---|
| **you-brain 桌面端** | 菜单栏常驻应用（macOS 先行，Linux 在 P1），不占 Dock。交互形态参考 magpie |
| **you-brain CLI** | 与桌面端同一个程序，提供 `you-brain` 命令，用于脚本、bot 接入和服务器管理 |
| **you-brain 服务器模式** | 同一个程序，以无界面后台服务运行在服务器上，适合担任主设备 |
| **浏览器插件**（独立项目） | 只负责把网页 AI 会话原文上报到 Drive，遵守 you-brain 协议 |

### 5.2 桌面端交互

- **菜单栏图标**：显示同步状态和提醒角标。
- **弹出面板**（点击图标或按全局快捷键）：
  - 今日：当天各设备的会话和提炼概要，按话题分组
  - 提醒：需要跟进的话题
  - 状态摘要：上次同步时间、异常提示
- **完整窗口**（从面板打开）：

| 页面 | 内容 |
|---|---|
| 今日 | 当天所有会话，按话题或时间查看；每个会话可以打开 Drive 原文 |
| 话题册 · 活跃 | 活跃话题列表（默认 10 个）；话题详情：概要、结论、待办、相关会话链接；可以改名、合并、拆分、改状态 |
| 话题册 · 历史 | 被移入历史区的话题；可以搜索，也可以重新激活 |
| 数字分身 | 各个变体（全量、精简、编码）的当前内容、历史快照对比、纠正记录 |
| 搜索 | 跨所有历史会话的语义 + 关键词搜索 |
| 设备 | 当前账号下所有设备及最后在线时间；指定主设备和网页会话处理设备 |
| 设置 | 见 5.3 |
| 状态 | 各来源的最近采集时间、同步队列、上次沉淀时间、错误日志 |

- **系统能力**：开机自启、全局快捷键、系统通知。

### 5.3 可配置项（全部在 GUI 中完成）

| 分组 | 配置项 |
|---|---|
| 账号 | Google 账号登录/切换；OAuth 凭据（官方测试模式或自带凭据） |
| Drive | 根目录（默认 `brain-hub/`）；数字分身文件列表与路径（默认为现有的全量、精简、编码三份） |
| 采集来源 | 每个来源的开关、扫描路径、包含/排除目录；是否保留工具调用（截断）；是否包含子代理会话；脱敏开关；明确展示"未采集范围" |
| 模型 | Provider（DeepSeek / GLM / Qwen / Kimi / OpenAI / Claude / Ollama / 任意 OpenAI 兼容地址）、模型名、API Key（只存本机钥匙串）、测试连接 |
| 提炼 | 会话空闲触发时间（默认 5 分钟） |
| 话题册 | 活跃话题上限（默认 10）；移入历史区的无活动天数（默认 30 天） |
| 沉淀 | 全局沉淀开关；沉淀时间（默认 03:00）；时区 |
| 提醒 | 系统通知开关；每日早报时间；每周回顾时间 |
| AI 工具接入 | MCP 注册（逐个客户端选择）；编码版数字分身写入各 CLI 指令文件（逐个选择）；skill 安装 |
| 界面 | 语言（中文 / English）、全局快捷键 |

除 API Key 外，配置通过 Drive 同步，新设备装好后自动继承。

## 6. 功能说明

### 6.1 会话采集

- **本地 CLI**：内置 Claude Code、Codex CLI、Grok Build、Cursor、Gemini CLI、Pi、T3 Code 七个来源；来源适配器是开放接口，社区可以继续扩展。
- **网页 AI**：由独立的浏览器插件上报；手机 App 登录同一账号后会话同步到网页版，因此一并覆盖。
- **采集规则**：默认只保留用户和助手的可见文本及图片，去掉 system prompt、隐藏推理、工具调用和 shell 输出，排除子代理会话，并对凭证做脱敏；可以按来源修改，修改只对之后的新会话生效。
- **噪音过滤**：只保留用户真正输入过内容的会话。CLI 启动时写入的 `AGENTS.md` 指令、环境上下文之类不算会话——Codex 每次启动都会留下这样一份文件，不过滤的话库里绝大部分「会话」其实是空的。
- **不再导入的来源**：T3 Code 从其他工具导入的会话（`import:` 前缀）跳过，原件由原工具负责，避免同一次对话被算两遍。
- **上传**：会话空闲后上传到 Drive。一个会话对应一个文件，后续增长时原地更新，**链接永远不变**。

### 6.2 会话提炼（白天实时）

- 会话空闲 5 分钟后，由**产生它的设备**做提炼；网页会话由**网页会话处理设备**提炼（已实现，真实插件格式未验证，见第 9 节）。
- 提炼一次产出：标题、概要、所属话题（归入已有话题或新建）、结论、待办。
- 会话继续增长时做**增量提炼**：只把"上次的提炼结果 + 新增消息"交给模型，不重读全文。
- 提炼结果同步到所有设备，换设备即可看到。

### 6.3 话题册

- **活跃区**：按最后活跃时间排序，默认保留 10 个，上限可以修改。
- **历史区**：超出上限的话题、或 30 天无活动的话题自动移入，GUI 中可以查看和搜索。
- **自动回归**：历史话题有新会话归入时，自动回到活跃区。
- **防碎片**：提炼时优先归入已有话题，只有明显是新事情时才新建；相似话题的合并建议放进每周回顾。
- **用户操作**：改名、合并、拆分、修改状态（进行中 / 待跟进 / 已完结 / 搁置）；手动操作优先于自动判断。
- **Drive 上的可读版本**（已实现）：`topics/TOPICS-latest.md` 是总览，每个话题有一个详情文件（链接固定），可以直接发给其他 AI 或在 NotebookLM 中使用。由主设备的沉淀步骤和白天 5 分钟防抖写入。

### 6.4 每日全局沉淀（P1，已实现）

由**主设备**（或接入的外部 bot）每天定时执行：

1. 重写话题概要，把白天各设备零散追加的结论整合通顺
2. 生成相似话题的合并建议
3. 更新数字分身，吸收用户的纠正
4. 刷新 Drive 上的话题总览和详情文件
5. 生成提醒

全局沉淀**可以关闭**，交给用户自己的 bot 直接读 Drive 来完成。状态页显示"上次沉淀时间"，超过 1 天未沉淀会标红。

### 6.5 数字分身

- 由一组可配置的文件组成，默认是用户现有的三份：全量版、精简版、编码版，沿用现有的版本快照命名。
- 各设备每天把数字分身拉取到本地。
- **编码版自动接入 AI CLI**：征得同意后，在各 CLI 的全局指令文件中写入一个托管段落，指向本机的编码版文件：
  - Claude Code：`@` 引入，内容自动加载
  - Codex / Gemini CLI / Grok Build：写一条强制读取的指令
  - Cursor：用户规则不是文件，给出手动配置的提示
- **全量版按需读取**：通过 skill 和 MCP 的 `get_portrait` 获取。
- **纠正**（P1，已实现）：用户在 GUI 里对某一段写纠正，下次沉淀时模型必须吸收；数字分身页显示每条纠正的状态。

### 6.6 提醒（P1，已实现）

| 类型 | 规则 |
|---|---|
| 停滞提醒 | 活跃话题有未完成事项，且 7 天没有新会话 |
| 历史话题提醒 | 历史区中有未完成事项的话题，**每周最多 5 条**，按未完成待办数与最近活跃排序；其余在每周回顾里汇总，不逐条弹出 |
| 每日早报 | 昨天的结论和未完成待办，以及今天建议跟进的 1–3 个话题 |
| 每周回顾 | 本周活跃话题、新增结论、停滞话题、历史区中未完成的话题、合并建议 |

- 每条提醒都可以选择：重新激活 / 标记完结 / 稍后提醒 / 不再提醒；连续被忽略 3 次后停止提醒。
- **今日页只显示前 2 条**，其余折叠，避免提醒把今日会话挤出首屏；展开后列表限高滚动。
- **渠道**：应用内（角标 + 面板）+ 桌面系统通知。通知只在当前正在使用的设备上弹出（最近 10 分钟内有键鼠活动或会话产生的设备）。

### 6.7 AI 工具读取

| 方式 | 说明 |
|---|---|
| MCP | 兼容 BrainHub 的工具名（`search_sessions`、`get_session`、`get_portrait`、`hub_status`），新增今日、话题、提醒相关工具。询问后再注册，可以跳过 |
| 本地 markdown | `~/.you-brain/` 下的 `TODAY.md`、`TOPICS.md`、`REMINDERS.md`、数字分身文件，零配置可用 |
| Skill | 为检测到的客户端安装对应的 skill |

### 6.8 多设备

- Google 账号就是 you-brain 的账号；GUI 和 CLI 都能查看该账号下的所有设备。
- 每台设备都保存完整的提炼数据，通过 Drive 自动同步，延迟在秒到分钟级。
- 模型 API Key 每台设备单独填写，只存在本机钥匙串中。

### 6.9 外部 bot 接入

- 外部 bot（Muse、Grok Bot 等）可以按公开协议注册为**虚拟设备**，代替主设备完成全局沉淀。
- 项目提供协议文档，以及给 bot 用的 skill / 提示词模板。
- bot 所在机器也可以直接安装 you-brain 服务器模式，通过 CLI 或 MCP 读写。

## 7. 典型场景

**场景 1：换设备接着干**
上午在 Mac 上用 Claude Code 讨论了 you-brain 的同步设计；下午到工作电脑上，点开菜单栏，"今日"里显示上午那个会话的概要和两条结论，归在"you-brain 设计"话题下。在 Codex 里说"看一下 ~/.you-brain/TODAY.md"，就能接着聊。

**场景 2：被提醒没跟进的事**
周日晚上的每周回顾里列出："you-brain 设计"还有 3 个待决策事项，已经 9 天没有新会话。点击"重新激活"，它回到活跃区。

**场景 3：AI 一开始就懂你**
新开一个 Codex 会话写代码，Codex 先读取编码版数字分身，知道你统一用 bun、偏好中文回复，不用再交代。

**场景 4：交给自己的 bot 沉淀**
你已经有一个 Grok Bot 在服务器上长期运行，于是关闭 you-brain 的全局沉淀，让 bot 按协议每晚读取 Drive、更新数字分身和话题总览，所有设备照常同步结果。

## 8. 与 BrainHub 的关系

| BrainHub 现有能力 | you-brain 中的对应 |
|---|---|
| 采集 4 个 CLI 来源 | 沿用，增加 Gemini CLI，来源适配器开放 |
| 上传到 `brain-hub/inbox/` | 沿用目录和格式；**改为原地更新，链接固定** |
| 本地语义搜索 | 沿用 |
| `get_portrait` 读取画像 | 扩展为多变体数字分身，接入 CLI，支持纠正 |
| 5 个 MCP 工具和 skill | 工具名兼容，新增今日、话题、提醒相关工具 |
| 定时上传任务 | 改为常驻后台服务，事件驱动 |

**迁移**：首次设置时检测本机的 BrainHub，询问后停用它的定时上传和 MCP 注册（可以一键恢复）。Drive 上的历史数据无需迁移，直接使用。

## 9. 里程碑

### P0：在 Mac 上自用，形成闭环

- 核心后台服务、七个 CLI 来源、按 BrainHub 格式上传（原地更新）
- 检测并接管 BrainHub
- 会话增量提炼（BYOK API / Ollama）
- 话题册：事件日志、本地合并、活跃区和历史区
- Drive 状态同步：事件、设备注册表、共享配置
- 数字分身：拉取到本地、编码版写入 CLI 指令文件、全量版 skill
- 本地 markdown 文件 + MCP
- 本地语义搜索
- 菜单栏 GUI：今日、话题册（含历史）、数字分身（只读）、搜索、设置、状态
- OAuth：官方测试模式 + 用户自带凭据

> P0 不做全局沉淀。数字分身继续由现有管道产出，you-brain 只负责读取和分发。

**验收标准**：在 Mac 上用任意 CLI 聊完，空闲 5 分钟后，"今日"里出现该会话的概要，并已归入话题；会话继续后，Drive 链接不变、提炼内容更新；Codex / Claude Code 新会话能读到编码版数字分身；MCP 能搜索到历史会话。

### P1：多设备与主动性

- 服务器模式 + CLI，可以担任主设备（已实现：`you-brain service install` 生成 launchd / systemd 单元；真实环境未验证）
- 每日全局沉淀及开关；虚拟设备协议正式发布（已实现：沉淀、`docs/protocol/`）
- Drive 上的话题总览和详情文件（已实现）
- 网页会话处理设备（已实现；真实浏览器插件格式未验证）
- 提醒：系统通知、每日早报、每周回顾、历史话题每周提醒（已实现；系统通知真机未验证）
- 数字分身纠正（已实现）
- Linux 支持（已适配：核心与桌面打包配置、手动触发的 Linux 打包工作流；未在 Linux 上出包）

**验收标准**：在设备 A 上聊完，几分钟内设备 B 的"今日"里能看到；主设备每晚完成沉淀，Drive 上的话题文件更新；停滞话题按规则提醒。

### P2：扩展

- Webhook 推送（已实现：主设备推送提醒与话题事件，签名与重试）
- 官方 OAuth 的受限范围审核
- 手机端

本机 CLI 订阅后端已实现（`grok` / `claude -p` / `codex exec` / `gemini` / `opencode`，含 grok 隔离），不再列入 P2。对照见[进度.md](./进度.md)。

## 10. 不在范围内

- 手机端采集（受 OS 沙盒限制，手机会话通过网页版间接覆盖）
- Windows 支持
- Adu、qian-chat 作为采集来源（以后可以通过适配器接口或协议接入）
- 维护者托管的云服务、遥测

# ADR-0006：TODO 使用 T3 串行执行与人工合并

状态：已接受（2026-11-16）。

## 背景

用户需要把开发 TODO 关联项目，自动处理其中优先级最高的一项，并在人工核对、合并到 `develop` 后继续下一项。执行入口确定为 T3，任务队列及人工合并入口由 U-Brain 提供。

## 决定

1. **独立的开发 TODO**：`/todos` 支持标题、说明、P0–P3 优先级和可选项目。项目来自本机 T3；项目默认暂停，由用户开启自动领取。未关联项目的 TODO 不执行。
2. **项目内串行**：P0 最高，同优先级按入队顺序。准备、执行、待核对、合并或失败中的任务均阻塞该项目下一项。暂停只影响后续领取，不取消当前任务。
3. **任务隔离**：从已有的本地 `develop` 创建 `task/<任务编号>` 及独立 Git worktree。保留所有权记录，恢复时核对仓库、分支及路径；不覆盖其他工作树或用户未提交修改。
4. **T3 负责执行**：适配 T3 0.0.45 的 HTTP orchestration 协议，本机 CLI 为 daemon 签发短期会话凭据，仅保存在内存。使用项目默认模型或最近会话的有效模型；权限沿用项目最近会话，无历史配置时用 `auto`。已有任务恢复和返工沿用该会话当前权限。T3 仍可依其权限模式请求批准。
5. **人工核对具体提交**：T3 必须完成最新一轮、结束输出，并在任务分支提交相关变更，才能进入核对。核对页提供摘要、提交 SHA、文件统计及有界 diff；长 diff 显示截断提示。确认请求必须携带核对过的 SHA，提交变化后必须重新核对。退回在原会话和原工作树继续处理。
6. **只快进合并**：确认后才推进本地 `develop`。目标分支已检出时要求工作区干净；未检出时用旧值比较更新 ref。分歧、未提交内容或任务分支改变均保留现场并报错。自动流程不 push、不部署、不删除任务分支或工作树。
7. **持久化与恢复**：状态在数据目录的 `tasks/board.json` 原子保存，不随 Drive 同步。先记录任务会话编号再派发，未知投递结果重用 command/message ID。人工批准的 SHA 先保存再合并；Git 已成功而状态保存失败时，恢复只补记同一批准版本，不另领任务。项目目录变化自动暂停并拒绝操作原任务。

## 使用前提与异常处理

- 本机 T3 运行中，`t3 auth session issue` 可用；连接地址沿用指挥台的 T3 设置。
- T3 项目路径为 Git 仓库根目录，已有本地 `develop`，且项目配置了可用模型。U-Brain 不自动创建基线分支或选择未知模型。
- 启动自动处理后，在 TODO 的“核对变更”中检查结果和测试；勾选已核对，再确认合并。合并后，保持开启的项目继续领取，队列清空后等待新任务。
- T3 连接失败保留队列；离线时仍可暂停领取。任务失败后可打开 T3 检查，完成修复或重试，再重新核对。
- `develop` 分歧或任务未提交时，先在 T3／Git 中人工处理，再使用“重试 / 重新检查”。自动流程不做 rebase、冲突解决或丢弃改动。
- 自动检查拒绝环境配置、凭据与密钥文件的变更；核对正文读取前即检查路径。人工仍需检查代码和验收结果，自动状态不能代替验收。

## 验证边界

回归测试覆盖队列、重启恢复、异常保存、HTTP 入口，以及真实临时 Git 仓库中的完整领取、核对和合并链路。T3 派发由模拟 HTTP 服务验证；本机真实 T3 已验证认证和只读项目接口，未派发真实模型任务。

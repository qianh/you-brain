# 知识库体验优化方案

> 日期：2026-11-10。状态：阶段一至三已改完代码（未提交、未打包实测），遗留项见文末“实施记录”。
> 目标：知识库用起来不卡顿，各类操作逼近 Notion，同时统一 UI 交互和样式。
> 依据：读代码和样式文件得出。没有打开实际界面，也没有做性能实测；阶段三的视觉项需要对着真实界面定稿。

## 现状判断

编辑器已经具备 Markdown 快捷输入、Tab 缩进、方向键跨块、格式快捷键、粘贴、手柄拖拽、多选、乐观更新和串行保存队列。离 Notion 的差距主要在三处：

1. **渲染**：任何状态变化都会重渲染整页所有块。
2. **撤销与保存的手感**：撤销是整块粒度；保存慢时会禁用部分操作。
3. **视觉细节**：版心、图标、动效、颜色没有统一。

功能数量不是短板，本方案不新增块类型。

## 阶段一：渲染性能

目标是打字、回车、移动光标时只重渲染受影响的行。不改数据链路。

1. **稳定 `editor` 对象。** `focus`、`structBusy` 改用 ref 读取，移出 `useMemo` 的依赖（`knowledge.tsx:1536`）。
2. **焦点请求只通知目标行。** 用一个按块 id 订阅的小 store（`useSyncExternalStore`）代替逐层下传的 `focus` prop；`assetBase`、`onFocusHandled` 改成稳定引用。
3. **块组件加 memo。** `EditableRow`、`BlockView` 包 `memo`。前提：
   - 本地改块树时没动的块保持原引用（核对 `replaceInTree`、`insertIntoTree` 等是否结构共享）。
   - 折叠状态作为 prop 传入，不再在渲染时调 `editor.isOpen`。
   - `chromeFor(...)` 移进行组件内部，不在父级每次生成新节点。
4. **拆分页面组件。** 拆成侧栏（目录、搜索、同步）、页头（封面、图标、标题、属性）、编辑区、数据库四块。共享状态（当前页、保存队列）放在父级的 ref 和少量 state 里。
5. **侧栏拖宽。** 拖动中直接写 `--knowledge-sidebar-w`，松手才写 state 和 localStorage。
6. **多选重绘。** `paintSelection` 只在选区变化或块列表变化时执行。
7. **缓存写入。** 整页比较改成按 `lastEditedTime` 加块引用判断；localStorage 写入挪到 `requestIdleCallback` 或离页时。
8. **长页面（可选）。** 顶层行加 `content-visibility: auto` 和 `contain-intrinsic-size`。先确认 macOS 的 WKWebView 和 Linux 的 WebKitGTK 都支持，再决定是否启用。

验收：

- 在 500 块的页面里打字或回车，React Profiler 显示只有 1～2 行提交，单次小于 16ms。
- 拖侧栏、在搜索框输入时，正文区不出现在提交列表里。
- 现有 `apps/web/test/pages/knowledge-*.test.ts` 全部通过。

## 阶段二：编辑手感

1. **撤销改成两级。**
   - 把每段连续输入（约 500ms 内或到词边界）记成一步文字快照，带块 id 和光标位置，进现有的历史栈。
   - ⌘Z 不再让当前行失焦；撤销后光标回到那一步的位置。
   - 块级操作（增删、移动、转换）仍是各自一步。
   - 重点测试：中文输入法组词期间、跨块连续输入、撤销到刚新建的块。
2. **保存状态降噪。** “保存中”只在挂起超过约 1.5 秒时显示。失败时在对应块上标记并提供重试，不只弹 toast。
3. **结构操作不再禁用菜单。** 拖拽已经走乐观路径（`relocateBlocks`）；菜单里的上移、下移、复制改用同一条路径并排队执行，去掉 `structBusy` 的禁用。同时核对带子块的块现在能否移动，能就放开限制。
4. **后台同步后刷新。** 知识库页订阅 `notion` 变更。收到后，当前页没有在途保存且没有正在编辑时，重读当前页和目录；否则等保存队列收尾后再对齐。
5. **手柄布局。** ＋ 和 ⋮⋮ 都放到块的左侧；拖动时显示半透明的块预览和蓝色落点线。
6. **同一块的连续修改合并。** 队列里同一块还没发出的文字修改合并成一次请求。

验收：

- 打错一个字按 ⌘Z 只撤销最近一段输入，光标不跳。
- 连续做 10 次结构操作，菜单始终可用，最终结果与 Notion 一致。
- 在 Notion 里改当前页，5 分钟内（下一次增量同步后）这里自动出现，不打断正在进行的输入。

## 阶段三：UI 与样式

| 项 | 现状 | 改成 |
|---|---|---|
| 正文版心 | 不限宽，左右各 48px | 居中约 720px，提供全宽开关；数据库和表格可以溢出版心 |
| 图标 | ⋮⋮、＋、▸、📄 是字符 | 用项目已有的 `Icon` 组件，统一尺寸和基线 |
| 动效 | 几乎没有 | 菜单、浮动工具条、切换器加约 120ms 的淡入和 4px 位移；折叠块、目录展开加高度过渡；遵守 `prefers-reduced-motion` |
| 颜色 | 48 处硬编码，无深色值 | Notion 的 9 种文字色和背景色提成 token，补深色主题的值；`knowledge.css` 里不再出现 hex 和 rgb |
| 侧栏选中项 | 紫色强调底加紫色字 | 中性灰底加正文色字 |
| 侧栏行 | 操作入口常驻或缺失不一致 | 统一行高和缩进；新建子页、更多操作只在悬停时出现 |
| 页头属性区 | 带边框的两列表格 | 无边框属性列表，标签在左、值可点击编辑 |
| 封面和图标 | 悬停操作样式不统一 | 统一成半透明小按钮 |
| 加载态 | “加载中”文字 | 骨架屏；切页时保留旧内容直到新内容就绪 |
| 键盘焦点 | 没有 `:focus-visible` | 菜单、目录、按钮补焦点环 |
| 保存状态 | 右上角浮动胶囊 | 放进页头固定位置，配合阶段二的降噪 |

验收：浅色和深色各截一组图（普通页、数据库行页、数据库、长页面），对照 Notion 逐项确认。

## 阶段四：数据链路（可选）

前三阶段做完后，如果“保存中挂很久”和限流失败仍然明显，再做这一阶段。

1. **本地先落盘。** 编辑先写本机索引和一份操作日志，后台按 Notion 限流逐条对齐。断网或限流时不丢、不阻塞，重启后继续。
2. **冲突处理。** 以块为单位，本地有未推送的修改时本地优先；否则以 Notion 为准。
3. **减轻写入响应。** 先确认前端是否用到页面视图里的 `markdown`；不用就改成按需计算，写入只返回变化的块。

风险：这是写入模型的改动，要覆盖中途退出、id 映射、失败重试几类场景。

## 做不到的部分

受 Notion 公开 API 限制（见 `docs/rea/notion-editor.md`）：

- 块类型转换和移动只能“新建再删除”，块 id 会变。
- 实时协作光标、评论。
- 数据库视图配置写回。

## 实施记录（2026-11-10）

代码层面已通过 `tsc`、`apps/web` 全部测试和 `vite build`；没有打开真实界面，下列效果都还没实测。

**阶段一**：已做 1、2、3、5、6、7；4（拆分页面组件）和 8（`content-visibility`）没做。
- 第 3 项 `BlockRow` 的 memo 靠 `OpenStateContext` 感知折叠变化，折叠状态一变所有行会重渲染一次。
- 第 4 项没拆：块行已 memo、`editor` 已稳定，搜索输入和侧栏拖动不再波及正文行；整页拆分风险大，等 Profiler 实测后再决定。
- 第 8 项要先在 macOS WKWebView 和 Linux WebKitGTK 上确认支持。
- 第 7 项的 localStorage 改为内存缓存，空闲 1 秒或离页时落盘。

**阶段二**：已做 1、2（仅延迟显示）、3、4、5（仅布局）、6。
- 第 1 项：一段输入停顿 0.5 秒（最长 3 秒）记一步；⌘Z 前先提交当前行的输入、不再失焦，撤销后光标落在变化处。未覆盖“词边界”切分；输入法组词、跨块连续输入需要手测。
- 第 2 项“失败时块上标记并重试”没做：现有失败模型是恢复为 Notion 版本，要改成保留本地失败状态，属于阶段四的写入模型改动。
- 第 3 项：菜单本来就没有被 `structBusy` 禁用，只剩待办勾选框用到，已移除 `structBusy`。
- 第 4 项：daemon 发 `notion` 变更后刷新目录；当前页在没有在途保存、没有在编辑时重读。
- 第 5 项：拖动半透明预览和落点线原本就有，这次只把 ＋ 移到左侧。

**阶段三**：已做版心（720px + 全宽开关）、图标、浮层动效、颜色 token（含深色值）、侧栏选中项、属性区、封面按钮、骨架屏、焦点环、`prefers-reduced-motion`。
- 没做：折叠块和目录展开的高度过渡、表格/数据库溢出版心、保存状态移入页头固定位置、侧栏行统一行高缩进。
- 其余图标位置（如块菜单里的 ☑、callout 的 💡）仍是字符。

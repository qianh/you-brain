# 托盘面板：只看提醒与模型额度 · 设计

> 2026-11-16 ｜ 状态：已按稿实现，待完整打包安装后由本人真机验收 ｜ 范围：菜单栏打开的小面板（`/panel`）。
> 本人已确认：拿掉同步告警条、保留底部三个按钮、其余按稿。
> 实现时的一处补充：首次接入的引导条（`StartGuide`，没配完 Drive、模型、采集时才出现）保留，它不是会话或话题。

## 为什么做

本人（2026-11-16）：菜单栏点开后只想看到两样东西，提醒，和各个模型的额度（比如 5h、7d）。现在面板里还有「今天的会话」「话题」「同步告警」，这些在完整窗口里都有，放在小面板里是重复。

同一次反馈里还有一个界面问题：提醒行的文字和右侧按钮不在一条水平中心线上。

## 目标

- 面板主体只有两块：提醒、额度。
- 额度按「近 7 天用过的模型」逐个显示，每个显示 magpie 给出的各个窗口（5 小时、7 天等）的已用百分比和重置时间。
- 额度数据取不到时不影响提醒，也不阻塞面板打开。

## 不做

- 不做额度告警、不做额度耗尽时的推送。
- 不做切换账号（magpie 自己能做）。
- 不改完整窗口里的任何页面。
- 不为 magpie 没有的模型自己去抓额度。

## 数据来源

本人选定（2026-11-16）：全部走 magpie，Claude Code 也走 magpie，不改 `~/.claude` 里的 statusline 脚本。

- 命令 `magpie accounts --json`，输出是账号数组：`agent`、`plan`、`windows[]`（`name`、`used`、`remaining`、`resetsAt`）、`readAt`，部分账号有 `balance`、`user`。
- 已核实（本机 2026-11-16）：claude 返回 `5 hours` 31%、`7 days` 54%、`7 days · Fable` 49%；codex 返回 `30 days` 1% 与额度余额；grok 返回 `7 days` 2%；zcode、workbuddy-ai、qoder 另有各自的窗口；copilot 和 kiro 登录已失效，没有窗口。
- **一次调用约 10 秒**（实测 9.7 秒，它要逐个向供应商查询）。所以界面绝不能等它：daemon 在后台取，界面只读缓存。
- 命令输出的头部有一行插件日志，解析前要先找到 JSON 起点。命令不存在、超时、输出解析失败，一律视为「暂时没有额度数据」。
- 邮箱（`user`）不进入面板、不写日志、不上传。

## 一、daemon 取数

- 新增 `GET /api/quota`，返回 `{ accounts: [...], readAt, stale }`，只读缓存，立即返回。
- 缓存由 daemon 后台刷新：启动时取一次，之后每 1 分钟取一次（本人 2026-11-16 改：5 分钟太长，跑任务时几分钟就能用掉很多额度）；面板或主窗口打开时若超过 1 分钟也触发一次（不等待）。同一时刻只跑一个 `magpie` 进程。
- 缓存按账号合并（2026-11-16 补：实测 magpie 偶尔对 Claude 只返回账号、不带窗口，整份替换会让 Claude 消失）：某个账号这次没读到窗口，沿用它上次的数字并标过期，面板显示「x 分钟前」，顶栏变淡；超过 1 小时仍读不到才去掉。账号用 agent 与登录名的短哈希区分，不保存邮箱。
- 单次调用 30 秒超时，超时就杀掉进程。失败时保留上一次的数据并标 `stale: true`，不清空。（我定的）
- 缓存只放内存，不落盘、不进 Drive、不进事件流。
- 没有 magpie（`which magpie` 找不到）时，接口返回空列表，面板不显示额度区，不报错。

## 二、哪些模型显示

2026-11-19 补充：在「设置 → 模型 → 额度展示」可勾选 Claude Code、Codex、Cursor、Grok 和 ZCode。未手动选择时，仍按近期采集记录默认勾选；首次手动修改后，顶栏和托盘只显示勾选且有数据的项，不再受采集记录限制，允许全部取消。偏好即时生效并由 daemon 保存在本机。Cursor 的订阅窗口同样来自 Magpie。

本人选定（2026-11-16）：近 7 天有会话的才显示。

- 用 `/api/status` 里已有的 `captures[]`（每个会话来源最近一次采集时间）判断，`lastCaptureAt` 在 7 天内算「近期用过」。
- magpie 的 `agent` 与会话来源的对应（我定的）：

| magpie | 会话来源 |
|---|---|
| claude | claude-code |
| codex | codex |
| cursor | cursor |
| grok | grok-build |
| zcode | zcode |

- 对应不上的账号（copilot、kiro、workbuddy-ai、qoder 等）不显示，因为 U-Brain 没法知道本人有没有用它们。需要时往这张表里加一行即可。
- 登录已失效、没有窗口的账号不显示。
- 同一个 agent 有多个账号时，只显示 `active: true` 的那个。（我定的）

## 三、面板长什么样

从上到下：

1. 头部不变（状态胶囊、打开窗口、刷新）。
2. **提醒**：沿用现有的 `ReminderList`，没有提醒时整块不出现。
3. **额度**：一张卡片，每个模型一小段。
   - 一行：模型名（Claude Code、Codex、Grok、ZCode），右侧是套餐（`pro`、`free`）。
   - 其后每个窗口一行：窗口名（5 小时、7 天，`7 days · Fable` 原样保留）、进度条、已用百分比、重置时间（「4 小时后」这种相对时间，悬停显示具体时刻）。
   - 数据是 `stale` 时，卡片标题旁显示「x 分钟前」。
   - 已用 ≥ 80% 用警示色，≥ 95% 用危险色。（我定的）
4. 底部三个按钮不变：立即同步、打开完整窗口、退出。

整个面板都没有内容时（没有提醒，也没有额度），显示现有的空状态。

**拿掉的**：今天的会话、话题、同步告警条。告警被拿掉后，同步出问题只能从头部状态胶囊看到颜色变化，点进完整窗口才有详情。这是本次改动的代价，请本人确认能接受。

## 三之二、主窗口顶栏

本人追加（2026-11-16）：主窗口顶栏的品牌名和导航之间也显示额度。

- 同一套数据和显示规则（`useQuota`），一次只显示一个模型：`Claude Code 5h 31% 7d 54%`，每 5 秒轮到下一个，鼠标悬停或键盘聚焦时停住。窗口名缩写，百分比按同样阈值着色。
- 导航菜单按整个窗口居中（左右两列等宽），不受额度条宽度影响。
- 悬停显示完整窗口名、百分比和重置倒计时。
- 窗口宽度小于 1100px 时隐藏，不挤压导航。

## 四、提醒行对齐

根因：`.reminder-banner` 用 `align-items: flex-start`（顶部对齐），文字一行 18px，按钮 24px，图标另有 `margin-top: 2px`，三者中心线差 1 到 3px。

- ~~折叠成单行时整行居中~~（2026-11-16 改：今天页没有折叠，没修到）。现在统一保持顶部对齐，文字、图标都按最高控件（28px 的忽略按钮，`--h-ctl`）补上方留白，按钮区最小高度也是这一行高；今天页和托盘的文字第一行、图标、按钮中心线一致（无头 Chrome 实测差 0.5px 以内）。
- 托盘里折成一行时，文字有换行**或被省略号截断**都显示「展开」（原先只看换行，单行长句看不全）。

## 留给实现者

- magpie 的调用放在 daemon 里，参照 `packages/core/src/llm/cli/` 的子进程封装，不新造一套。
- 代理环境变量：magpie 自己的日志显示它会带 `HTTPS_PROXY` 起插件，daemon 调用时不要改写环境。
- 额度区的文案进 `i18n`，中英都要。
- 面板的几何高度（`geometry.rs`）按新内容重新核对，不要出现不必要的滚动。

## 验收

1. 菜单栏点开，只有提醒和额度，没有会话、话题、告警。
2. 额度显示的 Claude 5h、7d 与终端 `magpie accounts` 一致。
3. 没有提醒时额度区正常；没有 magpie 时面板正常、无报错。
4. 拔掉网络或让 magpie 超时，面板仍立即打开，额度标「x 分钟前」。
5. 提醒行的文字、图标与按钮在同一条水平中心线上（折叠状态）。
6. 近 7 天没有采集过的来源（如 grok-build）不出现。

## 测试

- `daemon`：magpie 输出的解析（含头部日志行、空输出、坏 JSON）、超时、并发只跑一个、失败保留旧值并标 stale。用假的 magpie 可执行文件，不调用真的。
- `web`：模型选择与来源对应（近 7 天、失效账号、同 agent 多账号）、百分比阈值着色、相对时间。
- 样式：对齐问题没有可靠的单元测试办法，靠真机截图加代码里的样式规则核对。

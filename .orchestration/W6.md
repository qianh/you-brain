# 任务 W6：修复 .app 中外壳与 sidecar 同名互相覆盖（apps/desktop）

先阅读 /Users/john/private/ai/you-brain/.orchestration/COMMON.md 并遵守。只能修改 apps/desktop/**。
bun 1.3.11 路径：`~/.local/share/fnm/node-versions/v22.15.0/installation/bin/bun`（PATH 已加好）。

## 问题（主控实测）
`cd apps/desktop && bun run bundle --bundles app` 产出的 you-brain.app 中，`Contents/MacOS/` 只有一个 `you-brain`（14MB，是 Tauri 外壳）。原因：tauri.conf.json 的 `mainBinaryName` 是 `you-brain`，externalBin `binaries/you-brain` 打包后也叫 `you-brain`，sidecar（90MB 的 daemon）被覆盖，app 无法拉起 daemon。

## 要求
1. 把外壳主程序改名为 `you-brain-desktop`（mainBinaryName），productName 保持 `you-brain`，sidecar 保持 `you-brain`（用户可能会把它链接为 CLI）。检查 src/lib.rs 的 `locate_sidecar` / daemon.rs 在新名字下仍能找到 `Contents/MacOS/you-brain`，并且不会把外壳自身误认为 sidecar（补单元测试）。
2. 确认外壳拉起 sidecar 时设置了 `YOU_BRAIN_WEB_DIR=<Resources>/web`、`YOU_BRAIN_VENDOR_DIR=<Resources>/vendor`，并透传 `YOU_BRAIN_DATA_DIR`/`YOU_BRAIN_HOME`（测试隔离用）。
3. 重新 `bun run bundle --bundles app`（dist/daemon 已经构建好，不要重建 daemon）。
4. **实测**（用隔离目录，不要碰真实数据目录）：
   ```
   T=$(mktemp -d); APP=apps/desktop/src-tauri/target/release/bundle/macos/you-brain.app
   ls -la $APP/Contents/MacOS   # 应同时有 you-brain-desktop 与 you-brain（约 90MB）
   YOU_BRAIN_DATA_DIR=$T/data YOU_BRAIN_HOME=$T/home $APP/Contents/MacOS/you-brain-desktop &
   ```
   等待 `$T/data/daemon.json` 出现；用其中的 port/token 请求 `/api/status` 成功；`curl /panel` 返回注入了 token 的 Web UI；`ps` 中 daemon 进程的可执行文件位于 app 包内。然后结束外壳进程，确认 daemon 仍在运行（设计如此），再对 daemon 发 SIGTERM 并确认它退出、daemon.json 被删除。贴出全部输出。
5. `cargo test`、`cargo clippy` 通过。

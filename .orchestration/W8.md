## 要求

1. **Provider 枚举**：`LLM_PROVIDERS` 增加 `grok-cli`、`claude-cli`、`codex-cli`、`gemini-cli`、`kimi-cli`、`opencode-cli`。presets 里每项一个 label（如 `Grok（本机订阅）`、`Claude Code（本机订阅）`），新 kind `"cli"`，`requiresApiKey: false`，baseUrl 为空也要能通过 `resolveLlmTarget`。model 字段可空，空表示用该 CLI 自己的默认模型（不传 `-m`）。
2. **通用后端 `packages/core/src/llm/cli/`**：一个公共执行器 + 每个 CLI 一个 driver（driver 只负责：查找可执行文件、拼参数、解析输出、识别未登录）。公共执行器负责：
   - 参数数组启动子进程，**不经 shell**；大 prompt 用临时文件或 stdin 传入（避免 ARG_MAX），临时文件用完删除。
   - **cwd 固定为专用空目录** `<dataDir>/llm-cli`（导出函数统一计算，dataDir 可注入）。
   - 超时（默认 300 秒，可配置）和取消时按进程组杀掉子进程。
   - **同一进程内所有 CLI 后端全局串行**（最多 1 个并发）。
   - 错误统一抛 `LlmRequestError`：找不到可执行文件 → `"client"`「未找到 xxx 命令行，请先安装并登录」；未登录 → `"auth"`，并提示对应的登录命令；非 0 退出、超时、输出无法解析 → 相应类别。错误消息附 stderr 末尾 500 字，**不得包含 prompt 原文**。
   - 可执行文件查找顺序：选项注入 → 环境变量 `YOU_BRAIN_<NAME>_BIN`（如 `YOU_BRAIN_CLAUDE_BIN`）→ PATH → 表里列的常见安装位置。注意 daemon 由 launchd 启动时 PATH 很短，常见位置兜底必须有。
   - `complete()` 有 jsonSchema 时：有原生 schema 的 CLI 用原生；没有的在 user prompt 末尾追加「只输出符合以下 JSON Schema 的 JSON，不要任何其他文字」并附 schema，然后从输出中提取第一个完整 JSON 对象（处理 ```json 代码块包裹）。最终返回 JSON 字符串，与其他后端的返回约定一致（先读 refine/run.ts 确认调用方怎么解析）。
   - `test()` 复用 `runConnectionTest`。
3. **工具安全**：沉淀的输入是用户会话原文，可能包含诱导性内容。每个 driver 必须用该 CLI 能做到的最严格设置：禁止工具 / 只读沙箱 / 不自动批准。做不到完全禁用的（例如只能只读），在报告里逐个写明残余风险。
4. **防止自采集死循环（必须）**：you-brain 采集 claude-code、codex、grok-build、gemini-cli 的会话。CLI 后端在 `<dataDir>/llm-cli` 里运行产生的会话不能被采集，否则会形成「整理 → 产生会话 → 再整理」的循环。
   - grok：跳过 `~/.grok/sessions/<encodeURIComponent(专用目录)>`。
   - claude：用 `--no-session-persistence`，同时 claude 采集器跳过 `~/.claude/projects/` 下对应专用目录的项目目录（按 claude 的目录编码规则，先看本机实际目录名确认）。
   - codex：codex 采集器解析会话元数据里的 cwd，等于专用目录就丢弃。
   - gemini：跳过 `~/.gemini/tmp/<sha256(专用目录)>`（先在本机用 gemini 在临时目录跑一次，确认哈希规则）。
   - 每个采集器都写测试：构造一个普通会话和一个专用目录会话，断言后者被跳过。
5. **factory.ts**：kind 为 `cli` 时按 provider 选 driver 创建后端，不读 API Key。
6. **setup.ts**：
   - provider 提示改成分组展示：「API：deepseek / glm / … / custom」「本机订阅：grok-cli / claude-cli / …」。默认值仍为 deepseek。
   - 选 cli 类和 ollama 时不问 API Key。cli 类先检查可执行文件，找不到就清楚提示并中止本步。
   - 模型名提示：cli 类显示「模型名（留空用 xxx 自己的默认模型）」。
   - provider 为 `custom` 时，交互模式下如果没有 `--base-url` 且配置里也没有，追问「Base URL（OpenAI 兼容，如 https://api.x.ai/v1）：」，为空则报错。
   - 连接测试成功打印「模型连接成功」。
7. **设备缺 CLI 时的行为**：shared.json 会把 provider 同步到所有设备。某台设备选了 cli 类但本机找不到对应 CLI 时，沉淀要像「没有 API Key」一样跳过，并在状态里给出原因，不能崩溃或无限重试。复用现有「缺 Key 跳过」路径。
8. **设置页** `apps/web/src/pages/settings.tsx`：provider 下拉框分组显示新增项，选 cli 类时隐藏 API Key 和 Base URL 输入框。
9. **测试**：用假 CLI 脚本（写到临时目录，通过选项注入路径）覆盖每个 driver：成功、非 0 退出、未登录、非 JSON / 代码块包裹的 JSON、超时被杀。公共部分覆盖：全局串行（两个并发调用不重叠）、cwd 为专用目录、临时 prompt 文件被删除。**测试中不得调用任何真实 CLI。**
10. **真机冒烟（手动跑一次，不写进 bun test）**：对本机已安装的每个 CLI 各跑一次后端 `test()` 和一次带简单 schema 的 `complete()`，把结果（耗时、是否成功、报错）列表贴进报告。某个 CLI 因未登录等原因失败的，记录原因即可，不要尝试登录。跑完确认对应会话目录确实被采集器跳过。
11. 全量 `bun test`、protocol/core/cli/web 的 tsc 必须通过。完成后运行 `bun run build:daemon`，并按 W6 的方式重新打包 app（`apps/desktop/scripts/bundle.sh`）。

## 背景（用户真机实测失败）
```
➜ you-brain setup
检测到 BrainHub。接管配置、定时任务和 MCP 条目？ [y/N] y
已接管 BrainHub，备份在 …/migrate/1792324868642
Google 登录方式：1 官方  2 自带凭据 [1]：1
Google 登录未完成
```
原因：packages/core/src/auth/official-oauth-client.ts 里的官方凭据仍是占位符 `__YOU_BRAIN_GOOGLE_OAUTH_CLIENT_ID__`，打包脚本从未注入（参考 BrainHub 的 /Users/john/private/ai/ai-session-mcp/scripts/inject-official-oauth.mjs）。openGoogleDrive 静默返回 null，用户只看到"登录未完成"。

## 要求
1. **打包注入**：scripts/build-daemon.ts 在 `bun build --compile` 时注入官方凭据，来源为环境变量 `YOU_BRAIN_GOOGLE_OAUTH_CLIENT_ID` / `YOU_BRAIN_GOOGLE_OAUTH_CLIENT_SECRET`；若未设置，再尝试读取 `~/.config/you-brain/release.env`（KEY=VALUE 格式）。优先用 `bun build --define` 或构建时生成的临时模块实现，**绝不能把真实凭据写进仓库里的任何被 git 跟踪的文件**（源码中保持占位符，构建后 `git status` 必须干净）。校验 clientId 以 `.apps.googleusercontent.com` 结尾、secret 非空；都没有时构建仍成功，但打印醒目警告"此构建未内置官方 OAuth 凭据"。源码运行（bun packages/cli/src/index.ts）时也支持从这两个环境变量读取。
2. **明确的错误提示**：选择"官方"但没有内置凭据时，setup 立即提示"此版本未内置官方 OAuth 凭据，请选择 2 自带凭据，或使用正式构建"并回到选择，而不是静默失败。openGoogleDrive 的其他失败（用户取消、端口占用、invalid_grant、网络）都要给出具体原因，不要只有"登录未完成"。
3. **流程顺序**：setup 中 BrainHub 接管必须放到 Google 登录**成功之后**（先检测和询问，登录成功后再执行停用），避免旧的已停、新的未接上的空档。setup 可恢复设计保持不变：用户这次已经接管过 BrainHub（progress.brainhub = true），重新运行 setup 时不要重复接管、也不要报错。
4. **官方登录流程的实测**（不要真的完成授权，那需要用户）：用注入凭据后的编译产物，在临时数据目录运行 `you-brain setup`，选 1，确认它启动了本地回环监听并生成了包含正确 client_id 与 scope `https://www.googleapis.com/auth/drive` 的授权 URL（可以通过可注入的 openUrl/日志验证，或在 setup 中把授权 URL 打印出来供用户在浏览器打不开时手动复制——这一点本身也要实现）。测完结束进程。贴出输出时把 secret 打码。
5. 构建完成后执行 `cd apps/desktop && bun run bundle --bundles app` 重新打包 app（脚本会使用新的 sidecar）。
6. 补测试：注入逻辑（有/无凭据）、未内置凭据时的提示、接管顺序、重复运行 setup 不重复接管。
